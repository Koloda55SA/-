# Перенос данных из Firebase на Cloudflare (D1)

Разовый перенос: сотрудники, водители, путевые листы с подписями, отметки
допуска, переписка с поддержкой, CRM-заметки, оплаты, настройки организации,
заявки на удаление. В Firebase при этом ничего не меняется.

## Шаги

1. **Выгрузка.** Запустить локальную страницу и войти на ней администратором
   (тот же номер и пароль, что на старом сайте админки):

   ```
   node migration/server.mjs <папка для выгрузки>
   ```

   Открыть http://localhost:8766, нажать «Выгрузить». Данные сохраняются только
   в указанную папку на этом компьютере. В репозиторий их не класть.

2. **Проверка без записи:**

   ```
   node migration/import.mjs <папка выгрузки> --dry
   ```

   Показывает, сколько чего будет перенесено, и замечания (повтор номера,
   сотрудник без номера, второй запрос на допуск и т. п.).

3. **Запись в D1** (база очищается и заполняется заново, можно повторять):

   ```
   MIGRATION_SECRET=... node migration/import.mjs <папка выгрузки> \
     --api https://asem-pro-api.oon66517.workers.dev \
     --passwords <staff-passwords.txt от прошлого переноса, если был>
   ```

4. **После переключения** закрыть перенос — адреса `/api/migrate/*` исчезнут:

   ```
   wrangler secret delete MIGRATION_SECRET
   ```

## Пароли

- Администратор, сделавший выгрузку, входит на новый сайт со своим прежним
  паролем: страница выгрузки переносит не сам пароль, а его хэш.
- Водители входят с последними 6 цифрами номера, как при регистрации.
  Пароль водителю можно сменить на сайте.
- Медикам и мастерам создаются новые пароли: список в
  `<папка выгрузки>/staff-passwords.txt`. При повторном переносе с
  `--passwords` их пароли остаются прежними. Сменить пароль можно в
  «Сотрудниках».

## Проверка

`node migration/test/roundtrip.mjs http://127.0.0.1:8787` собирает выгрузку
«как из Firestore» с трудными случаями, переносит её на локальный сервер
(`wrangler dev`, `MIGRATION_SECRET` в `.dev.vars`) и проверяет вход и данные.
